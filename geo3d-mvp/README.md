# 3D Караганда — MVP

Сервис: клиент выбирает участок на 3D-карте → видит бесплатную сводку → платит → получает слои грунта, 3D-блок, разрез и отчёт для печати/PDF. Вы добавляете скважины через админку.

Без зависимостей, нужен только Node.js 18+.

## Запуск

Для показа и разработки (оплата без денег):

```powershell
cd geo3d-mvp
node server.js --demo
```

Без `--demo` оплата **выключена**: заказы не создаются, клиенту предлагается оставить заявку на изыскания. Это сделано намеренно, чтобы по ошибке не выставить сервис с «бесплатной» оплатой.

- Карта для клиентов: http://localhost:8095
- Админка: http://localhost:8095/admin (по умолчанию пароль `admin`, в боевом режиме он запрещён)

## Настройки (`.env`, образец — `.env.example`)

| Переменная | Что делает |
|---|---|
| `ADMIN_PASSWORD` | пароль админки; 10 неверных попыток за 15 минут блокируют вход на 15 минут |
| `PAYMENT_MODE` | `off` (по умолчанию) / `demo` (то же, что `--demo`) / `live` (боевой) |
| `PAYMENT_URL_TEMPLATE` | ссылка на оплату у провайдера с подстановками `{orderId}`, `{amount}`, `{returnUrl}` |
| `PAYMENT_WEBHOOK_SECRET` | секрет для проверки подписи вебхука |
| `PUBLIC_URL` | адрес сайта для возврата после оплаты |
| `TRUST_PROXY` | `1`, если сервер за nginx/Caddy (иначе лимиты считаются по адресу прокси) |

Боевой режим не запустится без нового пароля админки, секрета вебхука и ссылки на оплату.

## Оплата и безопасность

- **Токен покупателя.** Заказ имеет `id` (его знает платёжный провайдер) и отдельный секретный `token` (он же ключ отчёта). Отчёт открывается только по токену и только после оплаты.
- **Вебхук** `POST /api/payments/webhook` принимает JSON `{order_id, amount, status, signature}`, подпись `HMAC-SHA256(secret, "order_id.amount.status")`. Проверяются подпись, сумма заказа, повтор безопасен. **Это каркас:** у Kaspi Pay, Halyk epay и Freedom Pay свои форматы и подписи, под выбранного провайдера адаптер нужно доработать по его документации. Без договора и ключей с ним интеграцию проверить нельзя.
- **Ссылка возврата** содержит токен покупателя (`/?t=…`), провайдер его видит. Для вашей модели это приемлемо (он уже получил деньги), но учтите.
- **Ограничение запросов** (в памяти одного процесса): карта 40/мин, слои 20/мин, заказы 8/мин, заявки 5/час, события 60/мин на адрес. Это замедляет скрейпинг, но не останавливает его полностью: при массовой выгрузке с многих адресов нужны CAPTCHA или вход по аккаунту. Бесплатная часть уже огрублена: уровень воды до 0,5 м, расстояние до скважины до 10 м, ID скважины скрыт.
- **Экранирование.** Весь текст из файлов импорта очищается от `<` и `>` на сервере и экранируется при выводе на странице.
- **Заголовки** `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`.

## Границы покрытия (почему блоки бывают серыми)

Отсутствие данных не должно выглядеть как «всё хорошо». Для блоков «Опасные процессы», «Охранные и санитарные зоны» и «Инженерные сети» участок оценивается только там, где задано **покрытие**: полигон, внутри которого слой считается полным (вкладка «Слои участков» → «Покрытие данных»). Вне покрытия блок серый («нет данных»), общий светофор не может быть зелёным. Дата `as_of` старше года делает блок жёлтым («данные устарели»). Импортированные слои без покрытия остаются серыми, пока вы его не загрузите.

## Что в MVP

| Часть | Как работает |

| Карта | MapLibre. **Как в 2ГИС:** открывается плоской (2D), кнопка «3D» наклоняет камеру, включает рельеф, тени и объёмные здания OSM, повторное нажатие возвращает 2D. Подложка тёмная или спутник, точки скважин, участки и зоны. Внутри 3D-блока грунта кнопка скрыта, возврат ведёт в тот режим (2D или 3D), где был пользователь |
| Бесплатно | Достоверность, ближайшая скважина, уровень грунтовых вод |
| Платно | Слои грунта, 3D-блок 275×275 м, разрез запад–восток, страница отчёта |
| Защита данных | Слои грунта и интерполяция считаются на сервере; клиенту отдаются только после оплаты. Публично видны лишь координаты скважин |
| Нет данных рядом | Если до ближайшей скважины > 600 м, отчёт не продаётся — предлагается заказать изыскания |
| Админка | Очередь проверки скважин с автопроверками, импорт CSV по слоям, справочник грунтов, заказы, удаление демо |

При первом запуске создаются 30 **демо-скважин со случайными данными** (`DEMO-xx`). Перед показом клиентам загрузите свои и нажмите «Удалить демо-данные».

## Паспорт участка и свободные гектары

Карта показывает не только грунт, но и **можно ли строить на участке**. Источник требований: `geodesy-karaganda-data-requirements.md`.

**Три слоя данных** (вкладка админки «Слои участков», загрузка GeoJSON из QGIS в WGS84):

| Слой | Геометрия | Ключевые поля |
|---|---|---|
| Участки | Polygon | `status` (free / torgi / reserve / occupied), `cad_number`, `purposes`, `zone`, `max_floors`, `slope_pct`, `encumbrance`, `apz`, `tu` |
| Зоны ограничений | Polygon | `kind` (protection, sanitary, undermined, flood, slag, contamination), `name`, `regime` |
| Инженерные сети | LineString | `kind` (water, sewer, power, gas, heat), `capacity_free`, `owner` |

**Светофор по 8 блокам** (считается на сервере, функция `passport` в `server.js`): право и назначение, градостроительство, инженерные сети, рельеф, грунты, опасные процессы, охранные и санитарные зоны, достоверность данных. Общий цвет: красный, если красный хоть один блок; жёлтый, если есть жёлтый или нет данных; иначе зелёный. Результат зависит от типа объекта (ИЖС / многоэтажка).

**Что видит клиент**
- Бесплатно: цвет участка на карте, список свободных участков с гектарами и фильтром «от X га», 8 цветных точек паспорта.
- После оплаты: причины и цифры по каждому блоку (расстояния до сетей, свободная мощность, % участка в зоне), список недостающих документов (АПЗ, ТУ, изыскания, согласования), печатный отчёт.
- Сети публично не показываются, только расстояния и мощность в оплаченном отчёте (юридически уточнить, можно ли публиковать трассы).

**Ограничения текущей версии**
- Пороги светофора (уклон 5/10%, УГВ 2/3 м, расстояния до сетей 150/500 м, доля участка в зоне 30–50%) **ориентировочные**, их нужно согласовать с инженером-геотехником.
- Демо-слои (`DEMO-*`, 16 участков, 4 зоны, 12 линий сетей) синтетические. Удаляются кнопкой «Удалить демо-слои».
- Расчёты пересечений приближённые (выборка точек), для боевых данных заменить на PostGIS.
- Несущая способность и агрессивность грунтов пока не входят в модель.

## Аналитика (админка → вкладка «Аналитика»)

Собирается автоматически, без персональных данных: анонимный ID визита живёт, пока открыта вкладка; координаты округляются до ~10 м; IP не сохраняется.

| Показатель | Зачем |
|---|---|
| Воронка: визит → клик по участку → «Купить» → заказ → оплата | видно, на каком шаге теряются клиенты |
| Выручка, средний чек, конверсия визит→оплата | деньги и эффективность |
| Заявки на изыскания (статусы: новая / в работе / закрыта) | прямые клиенты для основного бизнеса |
| Карта спроса и «Где пробурить в первую очередь» | клики на участки без данных = потерянные продажи; показывает, где бурить следующим |
| Автовыводы («что говорят цифры») | самое слабое место воронки, доля потерянного спроса |
| Экспорт CSV заявок и заказов | для Excel / CRM |

Кнопка «Заполнить демо-аналитикой» создаёт 30 дней **синтетических** данных, чтобы показать дашборд; «Удалить демо-аналитику» убирает только их. Цифры демо (конверсия ~10%, выручка) придуманы и не отражают реальный спрос. Реальная конверсия обычно в разы ниже.

Хранение: `data/events.jsonl` (события), `data/leads.json` (заявки), `data/orders.json` (заказы).

## Скважины: структура, автопроверки, очередь проверки

Цель — чтобы данные из разных отчётов, лет и организаций совпадали и не давали разброса в модели. Вкладка админки «Скважины».

**Что хранится по каждой скважине**

| Группа | Поля |
|---|---|
| Паспорт | `id`, `report_id`, `doc` (документ-источник), `org`, `method`, `date` (бурения), `depth` |
| Координаты | `lng`, `lat`, `crs_src`, **`acc`** — класс точности: A (RTK / тахеометр, до ~0,1 м), B (GNSS, 1–3 м), C (по схеме, десятки метров), D (не подтверждены) |
| Высота | `z` — абсолютная отметка устья, `z_src` |
| Слои | по строке на слой: `layer_from`, `layer_to`, **`soil` — название как в журнале**, `cls` (класс модели, необязательно), `ige` |
| Вода | `gw_first` (появилась), `gw_stable` (установилась), `gw_date` |
| Свойства | `bearing_kpa` (несущая способность), `aggressive` |

CSV «по слоям»: одна строка = один слой, строки с одним `id` объединяются в скважину; шаблон скачивается в админке. Старый упрощённый формат (`id; lng; lat; gw; b1–b4`) тоже принимается.

**Справочник грунтов.** Название из журнала сопоставляется с одним из 5 классов модели по **первому слову** (основной грунт по ГОСТ 25100); побеждает самое длинное совпадение начала («песчаник» → скальный, «песок» → песок). Исходное название сохраняется. Неизвестные названия подсвечиваются, их можно добавить прямо в админке; изменение справочника перепроверяет все скважины.

**Автопроверки** (пороги в `CHECKS` в `server.js`, видны в админке; ориентировочные, согласовать с геологом):

| Ошибки (блокируют «проверена») | Предупреждения (нужна заметка геолога) |
|---|---|
| координаты вне Караганды; класс D; отметка устья вне 300–900 м | класс C; нет отметки, даты, документа, данных о воде |
| дата в будущем / не распознана | возраст больше 10 лет; скважина мельче 12 м |
| слои: не с 0 м, разрывы, перекрытия, подошва не глубже кровли | порядок слоёв отличается от модели; насыпной грунт |
| последний слой не доходит до глубины скважины | возможный дубль (ближе 2 м) |
| грунт не сопоставлен с классом | **сверка с соседями**: границы слоёв и УГВ расходятся с проверенными соседями (радиус 300 м) |
| вода глубже скважины | отметка устья отличается от соседей больше чем на 1,5 м |
| разные значения в строках одной скважины | |

**Шаблон для камеральщика** (`public/templates/`, ссылки есть в админке на вкладке «Скважины»):

| Файл | Что это |
|---|---|
| `boreholes-template.xlsx` | чистый шаблон: листы «Инструкция», «Скважины» (шапка скважины, вводится один раз), «Слои» (по строке на слой), «Экспорт» (формулы собирают CSV сами), «Справочник» |
| `boreholes-example-filled.xlsx` | заполненный пример на 3 скважины + самопроверка на листе «Инструкция» |
| `boreholes-example.csv`, `boreholes-template.csv` | готовая выгрузка примера и пустой заголовок |
| `INSTRUCTION.md` | инструкция: что откуда брать, класс точности, частые ошибки |

Шапка вводится один раз на листе «Скважины», а лист «Экспорт» подставляет её в каждую строку слоя, поэтому разные значения в строках одной скважины (ошибка E_INCONSISTENT) невозможны. На листах есть встроенные проверки (разрывы слоёв, глубина, формат даты, класс точности, координаты вне города, грунт не из справочника). Сохранять нужно лист «Экспорт» как CSV UTF-8. Сервер пропускает хвост пустых строк, который Excel дописывает после формул.

Пересборка шаблона после изменения справочника: `python tools/build_template.py public/templates` (нужен `openpyxl`). Копия справочника в шаблоне только для подсказок, рабочий справочник ведёт геолог в админке.

**Статусы и модель.** Любая загрузка попадает в статус «на проверке» (даже старый формат). В модель идут только «проверенные» скважины. Принять скважину с ошибками нельзя; с предупреждениями — только с заметкой. При перепроверке (изменили справочник, загрузили новых соседей) проверенная скважина с новой ошибкой автоматически возвращается на проверку. Повторная загрузка с тем же `id` заменяет скважину и снова отправляет её на проверку. В модели скважины взвешены по классу точности: A = 1, B = 0,7, C = 0,3. В паспорте участка показывается год бурения ближайшей скважины, данные старше 10 лет делают блок жёлтым.

**Ограничения.**
- Модель по-прежнему упрощённая: 5 классов в порядке «почва → суглинок → глина → песок → скальный». Скважины с другим порядком слоёв помечаются предупреждением, границы в модели обобщаются.
- Интерполяция идёт по **глубинам**. Учёт реального рельефа по абсолютным отметкам станет возможен, когда подключите вашу дроновую модель рельефа (DTM). До тех пор отметка устья используется только для проверок.
- Сверку отметки устья с рельефом дрона (порог 0,3–0,5 м) подключим вместе с DTM.
- Миграция: старые записи автоматически приводятся к новой структуре (класс B, без даты и отметки), статус сохраняется.

## Пилот на 20–30 скважин

Пакет для проверки процесса на малом объёме перед оцифровкой всего архива:

| Что | Где |
|---|---|
| План, критерии приёмки, отбор скважин, роли, протокол проверки геологом, риски, правила решения | `docs/PILOT.md` |
| Трекер (Excel, без формул): отбор, прогресс, замечания геолога, журнал решений, приёмка | `docs/pilot-tracker.xlsx` (пересборка: `python tools/build_pilot_tracker.py docs`) |
| Резервная копия данных перед началом и каждую неделю | `tools\backup-data.ps1` (копия в `backups\`, не попадает в git) |
| **Отчёт по пилоту** в админке (вкладка «Скважины» → «Сформировать») | частота замечаний, проверка «убрали скважину и предсказали по соседям» (leave-one-out) с рекомендациями по порогам, худшие скважины, грунты без класса, время до решения |

Проверка по соседям: каждую проверенную скважину предсказывают по остальным в радиусе 500 м (нужно ≥ 3 соседей) и сравнивают с реальной. Колонка «90% скважин ≤» показывает ошибку, которую не превышают 90% нормальных скважин; по ней геолог согласует пороги. Подсказки по порогам ориентировочные. Демо-скважины в отчёт по умолчанию не входят.

## Что ЗАМЕНИТЬ до публичного запуска

1. **Оплата.** Каркас боевого режима готов (токены, вебхук с подписью, проверка суммы), демо-оплата отключена по умолчанию. Осталось подключить конкретного провайдера: договор, ключи, формат подписи и ссылка на оплату по его документации.
2. **Админка.** Один пароль в заголовке (с блокировкой подбора) — только для старта. Нужны нормальный вход, HTTPS и ограничение по IP.
3. **Хранилище.** JSON-файлы подходят для сотен скважин. Дальше — PostgreSQL + PostGIS.
4. **HTTPS и хостинг.** За nginx/Caddy; ограничение частоты запросов (rate limit) на `/api/point` и `/api/orders`.
5. **Юридическое.** Оферта, политика данных, формулировка дисклеймера, права на данные скважин — с юристом.
6. **Отправка отчёта на email.** Сейчас ссылка показывается на экране; email только сохраняется в заказе.
7. **Модель грунта.** Сейчас простая IDW-интерполяция по 4 границам слоёв. Для реальных данных — типы слоёв из ваших журналов, учёт рельефа и геологических границ.
