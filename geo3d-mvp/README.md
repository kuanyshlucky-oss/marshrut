# 3D Караганда — MVP

Сервис: клиент выбирает участок на 3D-карте → видит бесплатную сводку → платит → получает слои грунта, 3D-блок, разрез и отчёт для печати/PDF. Вы добавляете скважины через админку.

Без зависимостей, нужен только Node.js 18+.

## Запуск

```powershell
cd geo3d-mvp
$env:ADMIN_PASSWORD = "ваш-пароль"
node server.js
```

- Карта для клиентов: http://localhost:8095
- Админка: http://localhost:8095/admin (по умолчанию пароль `admin` — смените)

## Что в MVP

| Часть | Как работает |
|---|---|
| Карта | MapLibre: 3D-рельеф, здания OSM, спутник, точки скважин |
| Бесплатно | Достоверность, ближайшая скважина, уровень грунтовых вод |
| Платно | Слои грунта, 3D-блок 275×275 м, разрез запад–восток, страница отчёта |
| Защита данных | Слои грунта и интерполяция считаются на сервере; клиенту отдаются только после оплаты. Публично видны лишь координаты скважин |
| Нет данных рядом | Если до ближайшей скважины > 600 м, отчёт не продаётся — предлагается заказать изыскания |
| Админка | Добавление скважины, импорт CSV (всё или ничего), флаг «проверена», заказы, удаление демо |
| Данные | `data/boreholes.json`, `data/orders.json` |

При первом запуске создаются 30 **демо-скважин со случайными данными** (`DEMO-xx`). Перед показом клиентам загрузите свои и нажмите «Удалить демо-данные».

## Паспорт участка и свободные гектары

Карта показывает не только грунт, но и **можно ли строить на участке**. Источник требований: `geodesy-karaganda-data-requirements.md`.

**Три слоя данных** (вкладка админки «Слои участков», загрузка GeoJSON из QGIS в WGS84):

| Слой | Геометрия | Ключевые поля |
|---|---|---|
| Участки | Polygon | `status` (free / torgi / reserve / occupied), `cad_number`, `purposes`, `zone`, `max_floors`, `slope_pct`, `encumbrance`, `apz`, `tu` |
| Зоны ограничений | Polygon | `kind` (protection, sanitary, undermined, flood, slag, contamination), `name`, `regime` |
| Инженерные сети | LineString | `kind` (water, sewer, power, gas, heat), `capacity_free`, `owner` |

**Светофор по 8 блокам** (считается на сервере, функция `passport` в `server.js`): право и назначение, градостроительство, инженерные сети, рельеф, грунты, опасные процессы, охранные и санитарные зоны, достоверность данных. Общий цвет: красный, если красный хоть один блок; жёлтый, если есть жёлтый или нет данных; иначе зелёный. Результат зависит от типа объекта (ИЖС / многоэтажка).

**Что видит клиент**
- Бесплатно: цвет участка на карте, список свободных участков с гектарами и фильтром «от X га», 8 цветных точек паспорта.
- После оплаты: причины и цифры по каждому блоку (расстояния до сетей, свободная мощность, % участка в зоне), список недостающих документов (АПЗ, ТУ, изыскания, согласования), печатный отчёт.
- Сети публично не показываются, только расстояния и мощность в оплаченном отчёте (юридически уточнить, можно ли публиковать трассы).

**Ограничения текущей версии**
- Пороги светофора (уклон 5/10%, УГВ 2/3 м, расстояния до сетей 150/500 м, доля участка в зоне 30–50%) **ориентировочные**, их нужно согласовать с инженером-геотехником.
- Демо-слои (`DEMO-*`, 16 участков, 4 зоны, 12 линий сетей) синтетические. Удаляются кнопкой «Удалить демо-слои».
- Расчёты пересечений приближённые (выборка точек), для боевых данных заменить на PostGIS.
- Несущая способность и агрессивность грунтов пока не входят в модель.

## Аналитика (админка → вкладка «Аналитика»)

Собирается автоматически, без персональных данных: анонимный ID визита живёт, пока открыта вкладка; координаты округляются до ~10 м; IP не сохраняется.

| Показатель | Зачем |
|---|---|
| Воронка: визит → клик по участку → «Купить» → заказ → оплата | видно, на каком шаге теряются клиенты |
| Выручка, средний чек, конверсия визит→оплата | деньги и эффективность |
| Заявки на изыскания (статусы: новая / в работе / закрыта) | прямые клиенты для основного бизнеса |
| Карта спроса и «Где пробурить в первую очередь» | клики на участки без данных = потерянные продажи; показывает, где бурить следующим |
| Автовыводы («что говорят цифры») | самое слабое место воронки, доля потерянного спроса |
| Экспорт CSV заявок и заказов | для Excel / CRM |

Кнопка «Заполнить демо-аналитикой» создаёт 30 дней **синтетических** данных, чтобы показать дашборд; «Удалить демо-аналитику» убирает только их. Цифры демо (конверсия ~10%, выручка) придуманы и не отражают реальный спрос. Реальная конверсия обычно в разы ниже.

Хранение: `data/events.jsonl` (события), `data/leads.json` (заявки), `data/orders.json` (заказы).

## Формат скважины

`id; lng; lat; gw; b1; b2; b3; b4` — координаты WGS84, `gw` — уровень грунтовых вод, `b1–b4` — глубина подошвы слоёв (почва, суглинок, глина, песок); ниже b4 — скальный грунт до 12 м. Шаблон CSV скачивается в админке.

## Что ЗАМЕНИТЬ до публичного запуска

1. **Оплата.** Сейчас `POST /api/orders/:id/pay` — заглушка, платит любой. Нужно подключить Kaspi Pay / Halyk epay / Freedom Pay: заказ становится `paid` только по подписанному вебхуку провайдера, эндпоинт-заглушку удалить.
2. **Админка.** Один пароль в заголовке — только для старта. Нужны нормальный вход, HTTPS и ограничение по IP/логин.
3. **Хранилище.** JSON-файлы подходят для сотен скважин. Дальше — PostgreSQL + PostGIS.
4. **HTTPS и хостинг.** За nginx/Caddy; ограничение частоты запросов (rate limit) на `/api/point` и `/api/orders`.
5. **Юридическое.** Оферта, политика данных, формулировка дисклеймера, права на данные скважин — с юристом.
6. **Отправка отчёта на email.** Сейчас ссылка показывается на экране; email только сохраняется в заказе.
7. **Модель грунта.** Сейчас простая IDW-интерполяция по 4 границам слоёв. Для реальных данных — типы слоёв из ваших журналов, учёт рельефа и геологических границ.
